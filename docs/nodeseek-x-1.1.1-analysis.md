# NodeSeek X 1.1.1 功能与安全分析

分析对象：用户提供的 `NodeSeek X` 1.1.1，共 2,430 行。

SHA-256：`751206e83bbb79efc0e927e1c8f07060e22a881707c1578f2be64cc7e2a89429`

对照目标：`Nodeseek Max-iSen` 1.0.8-lottery.18。

## 结论

- 未发现读取或上传论坛密码、Cookie、通知密钥的逻辑。
- 未发现 `eval`、`new Function`、WebSocket、混淆载荷或远程动态代码执行。
- 论坛写操作只有签到和屏蔽用户，均是功能声明范围内的官方接口。
- 大部分模块已经存在于 Max-iSen，且历史、过滤、用户信息、设置面板、移动端和新标签页处理更完整。
- 真正缺失的是回帖足迹和链接净化；多图床支持是同名模块中的缺失分支。
- 下拉加载已有主体功能，但缺少新加载头像的用户卡片绑定，已补齐。

## 原代码中发现的问题

### 短链解析会产生未提示的网络访问

原实现会在帖子加载时对正文中的短链接自动发出 `HEAD` 请求，失败后再发 `GET`。这会在用户点击前访问第三方服务，暴露 IP，并可能下载较大的响应。

Max-iSen 的处理：短链展开功能默认关闭；开启时仅发匿名 `HEAD` 请求，不用 `GET` 下载正文。

原默认规则还会全局删除 `ref`、`invite`、`affiliate`、`uid`、`pid`、`source` 等可能承载业务含义的参数。Max-iSen 默认只全局删除常见 UTM 和广告点击参数，其余规则仍可由用户在编辑器中自行配置。

### 短链和自定义图床权限不完整

原元数据只有 `@connect api.nodeimage.com`，但代码会请求多个短链域名和任意自定义图床，部分脚本管理器会直接拒绝这些请求。

Max-iSen 的处理：加入跨域连接权限；请求只用于用户主动选择的图床，以及用户明确开启的短链展开。

### 通配域名规则无法匹配

原规则写了 `*.youtube.com`、`*.bilibili.com`、`*.amazon.com`，匹配函数却把星号当普通字符，导致这些规则永远不生效。

Max-iSen 的处理：规则引擎会把 `*.` 规范化为主域及其子域，并有自动化测试覆盖。

### 回帖数据库升级会删除数据

原实现的 `onupgradeneeded` 会先删除已有对象仓库再重建；未来数据库版本变化时会清空足迹。

Max-iSen 的处理：只在仓库或索引不存在时创建，不删除已有记录。

### 首次同步后列表不会重新判定

原实现会在同步前给列表项目加“已检查”标记；同步完成再次扫描时，这些项目会被跳过。

Max-iSen 的处理：未查询到足迹时不永久锁定项目，同步完成后可立即重新标记。

### 浏览器兼容性

原回帖足迹直接调用 `navigator.locks.request`。不支持 Web Locks 的浏览器会导致整个模块失败。

Max-iSen 的处理：支持 Web Locks 时使用原生锁，否则使用带超时的用户脚本存储锁。

## 默认行为

- 回帖足迹默认关闭，首次开启时必须由用户确认同步。
- 链接净化默认开启，只做本地 URL 处理。
- 短链接展开默认关闭。
- NodeImage 仍是默认图床，继续使用原有登录和 API Key 流程。
- 其他图床只有用户主动切换并上传图片时才请求。
- 规则兼容模式开启时，回帖足迹同步和短链展开不会运行。
